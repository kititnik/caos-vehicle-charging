# Отчёт по индивидуальному заданию №1

**Исполнитель:** Хусточка Никита Вячеславович, БПИ253

**Вариант:** 33 - станция зарядки электромобилей

## 1. Условие задачи

На зарядной станции установлены устройства нескольких типов. Электромобили прибывают с различным уровнем заряда, ёмкостью аккумулятора и поддерживаемыми разъёмами. Автомобиль запрашивает совместимое устройство и требуемый конечный уровень заряда. Если подходящее устройство занято, автомобиль ожидает в очереди либо покидает станцию после тайм-аута. Станция имеет общий предел мощности, который диспетчер распределяет между активными зарядками (равномерно, приоритетно или адаптивно) тактами.

**Входные параметры:** 
- число, типы и мощность устройств; 
- предел мощности станции; 
- количество и характеристики автомобилей; 
- начальный и требуемый уровень заряда; 
- интервалы прибытия; 
- максимальное время ожидания; 
- стратегия выбора устройства и распределения мощности; 
- продолжительность такта.

**Инварианты:** 
- одно устройство обслуживает не более одного автомобиля; 
- подключение только к совместимому устройству; 
- суммарная мощность не превышает предел станции; 
- заряд не превышает ёмкость; 
- зарядившийся автомобиль освобождает устройство.

**Завершение:** после зарядки или ухода всех автомобилей, по окончании периода работы, либо по прерыванию пользователем.

## 2. Сценарий модели

Моделирование идёт тактами. Каждый участник модели - самостоятельный объект, подписанный на событие такта (`sim_subscribe`). Внутри такта обработчики вызываются в фиксированном порядке (`TickOrder`):

1. **Автомобиль** (`vehicle_on_tick`) - в свой такт прибытия запрашивает устройство у станции: если совместимых разъёмов на станции нет, уезжает, иначе встаёт в очередь. Если время ожидания истекло, а устройство так и не назначено, покидает очередь.
2. **Станция** (`station_on_tick`) - проходит очередь по порядку и подключает машины к свободным совместимым устройствам по стратегии выбора, затем распределяет мощность между занятыми устройствами.
3. **Зарядное устройство** (`charger_on_tick`) - передаёт в машину энергию `мощность × длительность такта`; при достижении целевого заряда отключает машину и освобождается.

Состояния автомобиля (`CarState`): `PENDING → QUEUED → CHARGING → DONE`, либо `QUEUED → TIMED_OUT`, либо `PENDING → INCOMPATIBLE`.

**Совместимость:** разъёмы хранятся битовыми масками (`TYPE1`, `TYPE2`, `CCS_COMBO`, `CHADEMO`, `TESLA_NACS`), у машины их может быть несколько.

**Стратегии выбора устройства:** `first_fit` - первое подходящее, `max_power` / `min_power` - с наибольшей / наименьшей мощностью.

**Стратегии распределения мощности:**
- `uniform` - поровну;
- `adaptive` - пропорционально недостающей до цели энергии;
- `priority` - машина, прибывшая раньше, берёт сколько может, остаток переходит следующей.

**Обеспечение инвариантов:**

| Инвариант | Где обеспечивается |
|---|---|
| одно устройство - одна машина | `charger_attach` отказывает занятому устройству |
| только совместимое устройство | `charger_attach`, `find_free_charger` проверяют маску разъёмов |
| сумма <= предела станции | распределение раздаёт не больше `power_limit` |
| заряд <= ёмкости | `vehicle_charge` обрезает заряд по цели |
| зарядившаяся машина освобождает устройство | `charger_on_tick` вызывает `charger_detach` |

## 3. Пользовательский интерфейс

Программа консольная, параметры задаются конфигурационным файлом:

```bash
./build/caos_vehicle_charging --config station.cfg
```

Формат конфигурации (`#` — комментарий):

```
power_limit 50          # предел мощности станции, кВт
max_wait 3              # максимальное ожидание в очереди, тактов
distribution uniform    # uniform | priority | adaptive
selection first_fit     # first_fit | max_power | min_power
tick 0.25               # длительность такта, ч
display_delay 500       # задержка отображения такта, мс
mode limited 40         # limited <тактов> | unlimited
log log.txt             # файл журнала (необязательно)

# charger <разъём> <мощность, кВт>
charger CCS_COMBO 50
# car <разъёмы через запятую> <ёмкость, кВт·ч> <старт, %> <цель, %> <мощность, кВт> <такт прибытия>
car CCS_COMBO,TYPE2 60 20 80 50 0
```

Обязательны хотя бы одно устройство и одна машина, `power_limit`, `tick` и `mode`.

Каждое событие выводится строкой с меткой такта `[t=N]` одновременно в stdout и в файл журнала. Вывод выполняется через файловые дескрипторы. Между тактами выдерживается задержка `display_delay` (`usleep`). В конце печатается итоговая статистика: причина завершения, число тактов и часов, количество машин по итоговому состоянию и заряд каждой машины.

## 4. Запуск и завершение

Сборка (проверено в Docker Ubuntu, `--platform linux/amd64`):

```bash
cmake -S . -B build && cmake --build build
./build/caos_vehicle_charging
```

| Ситуация | Поведение | Код возврата |
|---|---|---|
| все машины зарядились, ушли или несовместимы | «завершение: все машины обслужены» + статистика | 0 |
| `mode limited N` и прошло N тактов | «завершение: окончание периода» + статистика | 0 |
| Ctrl+C (SIGINT), в любом режиме | «моделирование прервано пользователем» + статистика | 130 |
| неверные аргументы | `Usage: ... --config <file>` | 1 |
| ошибка конфигурации | `<файл>:<строка>: syntax error / invalid value / missing required parameters` | 1 |

## 6. Дополнительные требования

| Требование | Реализация |
|---|---|
| комментарии в коде | есть во всех модулях |
| ввод-вывод через файловые дескрипторы | `logger.c`: `open` / `write` / `close` |
| завершение по окончании работы и по прерыванию | обработка SIGINT |
| сохранение лога со статистикой | ключ `log`, итоги в конце журнала (`stats.c`) |
| тестовые наборы и скрипт запуска | `tests/configs/*.cfg` (10 наборов), `tests/test.sh` проверяет код возврата и ожидаемые строки вывода |

ИИ при написании кода не использовался.
